# svp-service

![Version: 0.1.0](https://img.shields.io/badge/Version-0.1.0-informational?style=flat-square) ![Type: application](https://img.shields.io/badge/Type-application-informational?style=flat-square)

One service of the short-video platform on k3d, namespace svp: its Deployment, Service, ServiceAccount, NetworkPolicies, the migrate Job of a service with a database, the HTTPRoute of the gateway and, where a release asks for them, its HPA, PodDisruptionBudget or KEDA ScaledObject, or an Argo Rollouts canary in place of the Deployment. One chart for the six Go services and the web client, one release and one values file (base/services/<service>.yaml of svp-gitops) each.

Sinh bằng helm-docs từ `Chart.yaml` và comment `# --` của `values.yaml`: sửa hai file đó rồi chạy `make helm-docs`.
Giá trị của từng bản phát hành nằm ở `base/services/<service>.yaml` của `svp-gitops`.

## Values

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| canary | bool | `false` | Run the service as an Argo Rollouts Rollout with an analysed canary instead of a Deployment: Service <release>-canary beside the stable one, the release's HTTPRoute split between the two, AnalysisTemplate <release>-canary on Envoy's metrics of the canary backend. Only a release with an HTTPRoute can set it (the gateway, the web client): Envoy measures the canary on that route. |
| canaryLimits | object | `{}` | Limits of the canary's analysis, per release since what a good response time is depends on the service: p99Ms, the p99 in ms the canary must stay under; errorRatio, the share of 5xx among its responses that are not 4xx it must stay under. Required with canary set; the release's values file says why its numbers. |
| canaryPrometheus | object | `{"address":"http://kps-prometheus.svp-obs:9090","sigv4Region":""}` | Prometheus the canary's analysis queries. address: its HTTP API, no trailing slash (Argo Rollouts appends /api/v1/query); on EKS the query endpoint of the env's Amazon Managed Service for Prometheus workspace. sigv4Region: empty sends queries unsigned; set, the controller signs them with SigV4 in that region with its own credentials (EKS Pod Identity), which Argo Rollouts does only for an address on aps-workspaces. |
| egressTo | list | `[]` | Peers each release may reach, by name; see `ingressFrom`. |
| env | object | `{"OTEL_EXPORTER_OTLP_ENDPOINT":"http://otel-collector.svp-obs:4317","OTEL_EXPORTER_OTLP_INSECURE":"true"}` | Environment of every service; a values file adds its own. Secrets are never here: they come from Secret <service>-env (deploy/k8s/secrets.sh, from .env). |
| env.OTEL_EXPORTER_OTLP_ENDPOINT | string | `"http://otel-collector.svp-obs:4317"` | Traces, metrics and logs go to the Collector in svp-obs; until it runs, export fails with a rate-limited WARN and the service works as before. |
| errorTracking | bool | `false` | Report errors to GlitchTip (internal/sentryx): SENTRY_DSN comes from Secret sentry, which deploy/k8s/glitchtip-init.sh writes once GlitchTip runs (the DSN is GlitchTip's own, never in .env). The reference is optional: a pod started before that Secret exists runs with error reporting off, and Reloader restarts it once the DSN is there (the workload names Secret sentry in its reload annotation). media-worker reports no errors, as in compose. |
| externalPeers | object | `{}` | Peers that are not pods of the cluster where the cluster uses a managed service instead (EKS: Postgres on Amazon RDS, Kafka on Amazon MSK, Valkey on Amazon ElastiCache, objects on Amazon S3), by address: name of a peer above -> list of {cidr, ports}, each one rule of the egress of every release whose egressTo names that peer, and of the migrate Job for postgres. Such an entry takes the place of the peer's pods. Empty: every peer is the pods above. On EKS, postgres, kafka and valkey are the database subnets' CIDRs on 5432, 9096 and 6379; s3 is TCP 443 to each IPv4 range AWS publishes for S3 in the cluster's region (they change over time, so the list is read when the cluster's Terraform is applied), never 0.0.0.0/0: media-worker runs ffmpeg on uploaded files, and a worker taken over by a crafted file must not reach any other host. s3 also holds the EKS Pod Identity Agent, 169.254.170.23/32 TCP 80, where the pods that reach S3 (the only ones with an AWS role) get their credentials. An entry of 0.0.0.0/0 or ::/0 fails the render. |
| hpa | object | `{}` | HorizontalPodAutoscaler on CPU (metrics-server of k3s): {minReplicas, maxReplicas, cpuUtilization}. The utilization is a percentage of the container's CPU request, so resources.requests.cpu must be set (it always is, see below). |
| httpRoute | object | `{"host":"","name":"","sectionName":"https"}` | HTTPRoute on Gateway svp (svp-edge) to this release's Service, for a release that sets a host (the gateway, the web client); no other service is reached from outside the cluster. name: the route's name, empty for the release's name (the canary's Envoy cluster and the Rollout's traffic routing follow it). sectionName: the listener of Gateway svp it attaches to (chart svp-cluster): https for *.svp.localhost, https-apex for svp.localhost alone. |
| image.digest | string | `""` | Signed index digest of the image the pod runs; see `image.tag`. |
| image.repository | string | `""` | GitOps path: ghcr.io/anhnvcoder/svp-backend/<service>, from the release's values file. Dev path: `make k8s-up` passes k3d-svp-registry:5111/svp/<service>, the local registry under the name the nodes resolve on network k3d-svp. |
| image.tag | string | `""` | Empty on purpose. Dev path: `make k8s-up` passes the dev tag of the image it has just built (--set image.tag=...) and an empty digest. GitOps path: the promote pull request writes the release's commit (tag, for people) and its signed index digest (what the pod runs) into the values file. Both empty fails the render naming the release. |
| ingressFrom | list | `[]` | Pods each release may be reached from (ingressFrom) and may reach (egressTo), by name of the peers below; DNS is open to every pod of svp already (chart svp-cluster). The namespace denies everything else in both directions, so the lists are the whole of a service's traffic. Ingress is opened on the service's own port only. |
| keda | object | `{}` | KEDA ScaledObject on the consumer lag of a Kafka group, logged in through ClusterTriggerAuthentication keda-kafka (chart svp-data; Kafka user svp-keda): {minReplicas, maxReplicas, kafka: {topic, consumerGroup, lagThreshold}}. The broker is env.KAFKA_BROKERS, the one the service consumes from (kafka.svp-data.svc.cluster.local:9096 on k3d, the brokers of Amazon MSK on EKS). |
| localCA | string | `"local-ca"` | Secret of the release's namespace whose ca.crt is the CA the pods trust beyond the system's roots, mounted at /etc/svp-ca in the pods and the migrate Job: the local CA that Kafka, Valkey and Postgres of the cluster chain to (local-ca, chart svp-data), or on EKS the CA bundle of RDS (rds-ca, chart svp-cluster) for a service with a database. DATABASE_URL names it (sslrootcert=/etc/svp-ca/ca.crt); SSL_CERT_DIR=/etc/svp-ca adds it to the system's roots for Go, NODE_EXTRA_CA_CERTS=/etc/svp-ca/ca.crt for Node. Empty: the system's roots alone (a service without a database on EKS, whose Kafka and Valkey chain to a public CA). |
| migrate | bool | `false` | A service with a database runs `migrate` with its migrator role in a Job before each install and upgrade. |
| migrateResources | object | `{"limits":{"cpu":"500m","memory":"128Mi"},"requests":{"cpu":"50m","memory":"32Mi"}}` | Requests and limits of the migrate Job container. |
| pdb | object | `{}` | PodDisruptionBudget {minAvailable}: only for a workload that always runs at least two replicas: hpa.minReplicas >= 2, or no autoscaler at all (neither hpa nor keda) and replicas >= 2. With one replica a budget either blocks every node drain for good (minAvailable: 1) or allows everything (0), so a single-replica service has none. |
| peers | object | `{"collector":{"labels":{"app.kubernetes.io/instance":"otel-collector","app.kubernetes.io/name":"opentelemetry-collector"},"namespace":"svp-obs","ports":[4317]},"engagement-service":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"engagement-service"},"namespace":"svp","ports":[9103]},"envoy":{"labels":{"app.kubernetes.io/name":"envoy","gateway.envoyproxy.io/owning-gateway-name":"svp"},"namespace":"envoy-gateway-system"},"feed-service":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"feed-service"},"namespace":"svp","ports":[9104]},"gateway":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"gateway"},"namespace":"svp","ports":[8080]},"glitchtip":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"glitchtip"},"namespace":"svp-obs","ports":[8000]},"kafka":{"labels":{"app.kubernetes.io/name":"kafka"},"namespace":"svp-data","ports":[9096]},"postgres":{"labels":{"cnpg.io/cluster":"svp-pg"},"namespace":"svp-data","ports":[5432]},"pyroscope":{"labels":{"app.kubernetes.io/instance":"pyroscope","app.kubernetes.io/name":"pyroscope"},"namespace":"svp-obs","ports":[4040]},"s3":{"labels":{"app.kubernetes.io/name":"s3"},"namespace":"svp-data","ports":[9000]},"user-service":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"user-service"},"namespace":"svp","ports":[9101]},"valkey":{"labels":{"app.kubernetes.io/name":"valkey"},"namespace":"svp-data","ports":[6379]},"video-service":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"video-service"},"namespace":"svp","ports":[9102]},"web":{"labels":{"app.kubernetes.io/component":"server","app.kubernetes.io/name":"web"},"namespace":"svp","ports":[3001]}}` | The pods of each peer, by namespace and labels, and the pod ports a client reaches them on (NetworkPolicy sees the packet after a Service has been translated to a pod). The labels of svp-data are the ones its chart sets; those of svp-obs are the labels of the pinned upstream charts there (helm template). |
| podAnnotations | object | `{}` | Annotations of the pod template. A changed value makes a new revision without a new image: the canary drill of the lab changes one to run a canary of the code already running. |
| port | int | `0` | Port the process listens on (LISTEN_ADDR) and the Service exposes; unused with protocol none. |
| preStopSleepSeconds | string | `nil` | Seconds the container waits in a preStop sleep before it gets SIGTERM, for a process that exits at once on SIGTERM while Envoy may still send it requests: Envoy routes to pod addresses from the EndpointSlices, and needs a moment to drop a terminating pod. Kubernetes' own sleep action, so it needs no shell in the image. Empty: no preStop. |
| protocol | string | `"none"` | http: the gateway and the web client (probes on /healthz). grpc: the four gRPC services (Kubernetes' own grpc probe on the standard health service). none: media-worker (no port, no probe, no Service). |
| replicas | int | `1` | Replica count of a workload without an autoscaler. With hpa or keda set the chart renders no spec.replicas at all: a count in the manifest would be put back by every helm upgrade and by Argo CD's selfHeal each time the autoscaler changes it, the two fighting over the field. Such a workload starts with Kubernetes' default of 1 and its autoscaler raises it to its minimum. |
| resources | object | `{}` | Every container of the project has requests and limits; the values file sets them per service. |
| scratch | object | `{}` | Writable directories of a container whose root filesystem is read-only: name -> {mountPath, sizeLimit, medium}. |
| spreadAcrossNodes | bool | `false` | Spread the replicas over the zones, then over the nodes (topologySpreadConstraints on topology.kubernetes.io/zone, then kubernetes.io/hostname, both ScheduleAnyway): with two replicas, losing one zone or one node leaves one serving. Soft, so a cluster with one zone or one node still schedules them; k3d's nodes have no zone label. |
| terminationGracePeriodSeconds | string | `nil` | terminationGracePeriodSeconds of the pod; empty keeps Kubernetes' 30 s. |
